# Retenues sur salaire — plan de mise en œuvre

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** plusieurs crédits par particulier ; retenue automatique sur le salaire de l'agent des crédits d'un client dont le plus ancien crédit non payé a plus d'un mois, et des dépenses marquées ; remboursement, pardon, agent d'un crédit choisi par l'administrateur.

**Architecture:** `sales.over_limit = 2` pour un crédit malgré un crédit en cours ; `sales.staff_id` ; table `staff_deductions` (mouvements, jamais réécrits) tenue à jour par `syncDeductions()` (`src/deductions.js`) ; `src/payroll.js` les ajoute au calcul du mois.

**Spec:** `docs/superpowers/specs/2026-10-19-retenues-design.md`

## Global Constraints

- Français partout ; pas de texte d'explication hors Réglages ; journal `agents` ; base en version 32 avec test de migration ; `fail()` et `transaction()`.
- L'administrateur peut tout ce que peut le gérant (`requireRole('manager')` le laisse passer) ; `requireAdmin` seulement pour l'agent d'un crédit.

## Review Focus

- Un crédit payé en partie puis entièrement : deux rendus, total retenu 0.
- Un crédit changé d'agent après la retenue : rendu à l'ancien, retenu au nouveau.
- Une dépense marquée dont le montant est corrigé : la différence.
- Un crédit d'avant « Paie depuis » de l'agent : jamais retenu.
- Un client abonné : jamais retenu.
